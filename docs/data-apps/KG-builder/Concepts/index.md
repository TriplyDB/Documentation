# TriplyDB knowledge graph builder 
## Key Concepts

**Asset (TriplyDB Asset)**
A file uploaded to a TriplyDB dataset that can be referenced by pipelines and flows. KG Builder accepts `.txt`, `.rtf`, and `.doc` files stored as Assets as input documents.

**Classes, properties, and simple constraints**
The three types of ontology building blocks that KG Builder extracts. Classes represent entity types (e.g. `Employer`, `Contract`). Properties represent relationships and attributes between them. Simple constraints describe rules about how classes and properties may be used, expressed as SHACL shapes.

**CONSTRUCT query**
A SPARQL query type that produces an RDF graph as output. KG Builder uses a CONSTRUCT query to transform the LLM's extracted entities and properties into SHACL shapes and OWL class/property definitions.

**Cost ceiling**
A monetary limit you can set before running KG Builder. If the system's pre-run cost estimate exceeds the ceiling you define, the run is cancelled before any LLM calls are made. This protects against unexpectedly large extractions.

**Cost estimate**
Before executing the LLM pipeline, KG Builder estimates the expected execution time and cost based on the size and number of input documents. You review this estimate before confirming the run.

**Data Model Editor**
The TriplyDB interface for viewing and editing ontologies — classes, properties, and constraints — in a structured, form-based UI. KG Builder writes its output to a dataset graph; you then open that graph in the Data Model Editor to review and refine the extracted ontology.

**Flow (TriplyDB Flow)**
A pre-configured pipeline in TriplyDB that executes a series of steps in sequence. KG Builder is packaged as a flow called `KG_builder`, accessible from the **Flows** tab in your TriplyDB account.

**LLM pipeline**
The sequence of steps in KG Builder that uses a large language model to identify classes, properties, and constraints in the input text and convert them into structured RDF. The LLM is provided by Triply and operates in a confidential environment — your data is not used for model training.

**Precision**
The proportion of extracted ontology elements that are correct. With the default Triply-provided LLM, KG Builder targets precision ≥ 60% — meaning most extracted elements are accurate, but some review is expected.

**Prefix alias**
A short, lowercase abbreviation used as the namespace prefix for the URIs generated by KG Builder — for example, `wtp` for the Dutch Pension Act.

**Prefix namespace**
The base URI that KG Builder uses to construct URIs for extracted classes and properties.

**RDF (Resource Description Framework)**
The W3C standard for representing data as subject–predicate–object triples. KG Builder produces RDF triples representing the extracted ontology.

**Recall**
The proportion of ontology elements present in the source text that KG Builder successfully extracts. With the default Triply-provided LLM, KG Builder targets recall ≥ 80% — meaning most relevant concepts are captured, though completeness is not guaranteed.

**SHACL (Shapes Constraint Language)**
A W3C standard for defining and validating the structure of RDF graphs. KG Builder automatically generates SHACL shapes to express the simple constraints it extracts from the source text.

**Shapes namespace**
The base URI that KG Builder uses to construct URIs for the generated SHACL shapes. Kept separate from the prefix namespace to distinguish schema definitions from instance data.

**TriplyDB dataset**
A container in TriplyDB that holds one or more named graphs, together with associated metadata, services, and assets. KG Builder writes its output to a dataset you specify.
